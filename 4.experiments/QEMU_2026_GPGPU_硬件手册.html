1. 概述¶

GPGPU 是为 QEMU 训练营定制的虚拟 PCIe 3D 加速器设备。其设计目标是提供一个覆盖 GPU 关键子系统的硬件抽象，用于：

  • PCIe 设备建模（BAR 映射、MSI-X 中断、配置空间）
  • DMA 引擎建模（Host↔VRAM 双向传输）
  • SIMT 教学执行模型（逐 Lane 推进、线程层次）
  • RISC-V 指令集解释器（RV32I + RV32F + 低精度浮点扩展）

2. 文档约定¶

2.1 数值与端序¶

  • 除非特别说明，所有数值均为十六进制，形如 0x1001_8000（下划线仅用于分组）。
  • 地址均为 字节地址（byte addressable）。
  • 所有多字节寄存器访问均按 小端序（little-endian） 解释。

2.2 术语¶

  • 未定义（undefined）：实现可以产生任意结果；软件不得依赖其行为。
  • 实现定义（implementation-defined）：实现必须在某处给出选择；若未给出，软件仍不得依赖。
  • R / W / R/W / W1C：分别表示只读、只写、可读写、写 1 清除；W1C 位写 0 不改变状态。表中复位值指设备冷复位或 GLOBAL_CTRL.RESET 后的值，单独 CP 复位的影响另行列出。

3.4 双进程的 BAR、DMA 与中断路径¶

[DESIGN] A57 Linux 运行在进程 A，通过 vfio-user-pci 访问进程 B 的 gpu0。进程 B 使用 gpgpu-cp machine，包含原有寄存器、VRAM、DMA、中断与计算解释器，以及由 TCG 执行的原生 RV64 CP。CP 默认保持复位；计算任务统一经 AQL 队列交给 CP，DMA 引擎用于存储拷贝。

进程 A：A57 Linux
  └─ PCIe 设备代理
       ├─ 配置空间、BAR0/BAR2/BAR4 请求 ─→ 进程 B：GPGPU
       ├─ PCI DMA 接口 ←─ B 的读写请求       ├─ 原计算解释器
       │    └─ SMMUv3（启用时）→ Host RAM    └─ 原生 RV64 CP
       └─ Linux 驱动 ←─ 完成与错误中断            └─ 访问同一份 VRAM

none 与 smmuv3 都使用 x-dma-via-socket=on：B 把设备 DMA 地址、方向和数据请求发送给 A，A 调用该 PCI 设备的 DMA 接口，并返回数据或错误。SMMUv3 的翻译、权限检查和故障记录保留在 A。该启动选项只选择通信方式，不增加硬件寄存器。

BAR 访问通过消息转发，MSI-X 表和屏蔽状态在两端同步。Signal 完成通过 IH 通知；DMA 完成和错误事件沿相应向量传给 A 的 Linux 驱动。DMA 继续同步搬运数据，并通过原定时器报告完成。本版不支持断线重连和迁移。

4.3 MMIO 访问规则¶

  • BAR0 寄存器采用小端、4 字节对齐的 32 位访问。64 位地址由低、高两个寄存器保存，完整地址为 (HI << 32) | LO；不得用一次 64 位访问代替两次寄存器访问。
  • BAR2 VRAM 支持 1～8 字节访问。BAR4 Doorbell 的访问规则见 11.5 节。
  • 表中标记为保留的位必须写 0；读值及非法访问的处理以各寄存器组的规定为准。
  • 落在单一寄存器子区域内的 BAR0 非法宽度或未对齐访问不更新目标寄存器，读返回 0，并置位 ERROR_STATUS.INVALID_CMD。IH 区域还记录 PROTOCOL 故障。HQD 和 CP 本地入口的权限见各节。
  • CP 控制窗口只开放分发、IH 和全局错误入口；访问其他寄存器组时读取返回 0，并置位 ERROR_STATUS.INVALID_CMD。组内保留位置按各组规则处理。未映射的 CP 地址产生访存异常，HQD 槽号不截断或折返。

4.5 GPU 物理存储映射

CP 或计算线程给出用户地址后，GPUVM 开启时先查页表，关闭时直接使用该地址。两条路径最终交给同一个物理入口。当前 64 MiB VRAM 的地址布局为：

[0x0000_0000, 0x0400_0000)     VRAM
[0x0400_0000, 0x1_0000_0000)   Outbound → Host IOVA → PCIe DMA

GPUVM 开：GPUVA → 页表 → GPU 物理地址 ─┐
GPUVM 关：输入就是 GPU 物理地址 ───────┴→ 公共物理入口 → VRAM 或 Outbound

一般配置中，VRAM 结束地址就是 Outbound 起点 vram_size，中间没有空洞。窗口配置与换算见第 18 章。RV64 CP 自己的代码、栈和寄存器仍按 4.4 节的 CP 本地地址解释。

6.5 软复位行为¶

写 GLOBAL_CTRL.RESET = 1 后，设备停止 CP 与计算任务，清零全局控制、错误、中断、分发配置、DMA、HQD、Doorbell 提示和 IH 状态；GPUVM 清零，Outbound 恢复初始布局并停用；GLOBAL_STATUS 恢复 READY，DISPATCH_STATUS 恢复 IDLE。已连接的 CP 保持复位，启动入口与 Host 窗口基址清零。VRAM 内容保留。单独 CP 复位的范围见 10.5 节。

0x0818IH_CTRLR/W / R0使能与通道复位。

IH_BASE 按 4 KiB 对齐，基址加容量的完整范围不得溢出。只有 ENABLE = 0 且 BUSY = 0 时，Host 才能改写基址和容量；使能时检查配置。向只读项、未定义位置或以错误权限写入，记录 PROTOCOL 故障，不改变目标配置。

7.4 IH_CTRL 与 IH_STATUS 位域

寄存器位名称行为
IH_CTRL0ENABLER/W，复位为 0。写 1 启用；写 0 停止接受记录。
IH_CTRL1RESET复位请求，不锁存。仅已禁用且无在途写入时可写 1，不能与 ENABLE 同时置位。
IH_CTRL31:2Reserved读零，写入必须为 0。
IH_STATUS0BUSY当前有记录写入；复位为 0。
IH_STATUS1FAULT锁存通道故障；复位为 0。
IH_STATUS15:8ERROR_CODE首次故障编号，后续故障不覆盖；复位为 0。
IH_STATUS23:16LAST_SUBMIT_RESULT最近一次 CP 提交结果；复位为 0。非提交事件不覆盖此字段。

ERROR_CODE 和 LAST_SUBMIT_RESULT 使用以下独立编号，分别保存；它们不是位掩码。

值名称含义
0OK无故障；提交结果中表示记录与 WPTR 已发布。
1DISABLED通道未使能时提交。
2CONFIGRing 基址、容量或范围非法。
3FULLRing 已满，没有可写槽位。

故障置位 IH_STATUS.FAULT 和全局 ERROR_STATUS.IH_FAULT，经 IRQ_STATUS.ERROR 通知。已有故障时拒绝新记录；首次满环提交可得到 ERROR_CODE = 3，再次提交时前者保持 3，而 LAST_SUBMIT_RESULT = 7。

有效的 IH_CTRL.RESET 清零 WPTR、RPTR、BUSY、FAULT、首次故障和提交结果，保留基址、容量及 Host Ring 内容。全局错误和中断锁存位须分别按 W1C 规则确认；通道复位不代替错误确认，也不证明计算任务已停止。

7.5 IH_SUBMIT 与记录发布

CP 在固件私有 VRAM 的 0x03c0_0000～0x03ff_ffff 内准备一条 32 字节、小端记录，起始偏移至少按 8 字节对齐，整条记录必须位于该范围内。先保证记录内容可见，再将起始偏移写入 IH_SUBMIT。写操作同步返回；CP 随后读取 LAST_SUBMIT_RESULT，此时可复用临时缓冲区。

记录内偏移位宽含义
0x0032类型：1 = SIGNAL_NOTIFY，2 = QUEUE_ERROR，3 = DEVICE_ERROR。
0x0432HQD 槽号：SIGNAL_NOTIFY 为 2～3；QUEUE_ERROR 为 0～3；DEVICE_ERROR 为 0xffff_ffff。
0x0864完整 MQD 物理字节地址，至少按 8 字节对齐；DEVICE_ERROR 填 0。
0x1032类型 1：非零事件编号；类型 2：CP_HQD_ERROR 编号 1～10；类型 3：必须为 GPGPU_ERR_FIRMWARE（bit 4），否则按 RECORD 错误拒绝；设备只锁存 FIRMWARE。
0x14～0x1f96保留，填 0。

令 N = IH_SIZE / 32，记录地址为 IH_BASE + (IH_WPTR mod N) × 32。WPTR、RPTR 均按模 2^32 推进，不是字节偏移。(WPTR − RPTR) mod 2^32 = N 时 Ring 满，设备拒绝新记录，不覆盖未消费记录；写入失败不推进 WPTR。

设备先完整写入记录，再发布 WPTR，最后置位 IH 中断。Host 读取发布进度并同步后消费记录，再写回 RPTR；新 RPTR 的前进量不能超过尚未消费的记录数。更新 RPTR 后，向 IRQ_ACK 的 bit 2 写 1；若 Ring 仍非空，IH 位立即重新置位并再次通知。ACK 不推进 RPTR，也不清除 IH 故障；重新使能 IH 中断时，非空 Ring 同样产生通知。

8.2 编程模型¶

CP 在 IDLE 时写入代码入口及长度、参数地址及长度、Grid/Block 尺寸和源队列标识，最后向 DISPATCH 写 1。设备保存配置与当前 GPUVM 状态，校验通过后进入 BUSY；校验失败直接进入 FAILED。

执行器分段推进任务，同一个 Warp 继续执行时保留寄存器、PC 和启动状态。计算及相关访问结束后发布 DONE 或 FAILED。CP 读取结果并写 ACK 后，执行器才接受下一任务；成功完成沿 Signal、通知槽、IH、INVALID Header、消费进度的顺序收尾。

参数基址至少按 8 字节对齐，代码和参数的完整范围都必须落在 32 位地址空间内；无参数任务也提供 4 字节占位参数。各轴 Grid/Block 尺寸必须非零，每组最多 1024 个线程，最多 4096 个工作组，实际线程总数最多 65536；未使用轴填 1，SHARED_MEM_SIZE 填 0。

10. CP 控制寄存器¶

CP 的低地址映射到相同偏移的 VRAM。默认 64 MiB 配置中，0x03c0_0000～0x03ff_ffff 保留给 CP 固件，入口为 0x03c0_0000，最后 64 KiB 为栈。Host 经 BAR2 装载固件，写入入口并确认存储可见后解除复位。

10.1 寄存器映射（0x0500）

BAR0 偏移寄存器访问复位值定义
0x0500CP_CTRLR/W0x0000_0003连接 CP 时复位保持且 PRESENT = 1；未连接时读零。

10.2 CP_CTRL（0x0500）

位名称访问复位行为

10.3 CP_RESET_VECTOR（0x0504）

bits 31:0 保存启动字节地址，复位为 0。仅在保持复位时可写，地址必须位于 VRAM 内且按 2 字节对齐；非法地址或运行中修改保留原值，并置位 ERROR_STATUS.INVALID_CMD。未连接原生 CP 时，CP_CTRL 与 CP_RESET_VECTOR 都读零、写入忽略。

10.4 CP 访存窗口与 IOVA_BASE

CP 通过 0x8000_0000～0x8000_ffff 的 64 KiB 窗口访问 GPU 存储，支持按访问宽度对齐的 1/2/4/8 字节读写。下列 32 位小端寄存器保存目标基址和访问上下文，仅 CP 可访问，Host 无 BAR0 对应项。窗口的基址寄存器保留 IOVA_BASE 名称，实际保存输入 GPU 地址；访问域决定该地址是否需要翻译。

CP 本地地址寄存器（32 位）访问复位值位域

10.5 复位范围与固件替换

CP 单独复位保留 VRAM、启动入口、HQD、IH、DMA、分发和中断状态，清零 CP 访存窗口配置及 GPUVM 固件握手，保留 GPUVM 上下文与 TLB；它不停止已有计算任务或清理队列。GLOBAL_CTRL.RESET 停止计算并复位设备寄存器，保留 VRAM；设备冷复位还清零 VRAM。

替换固件前须确认相关计算和访存已结束，再保持 CP 复位并读回确认、装载固件、设置入口、保证写入可见，最后解除复位。仅观察到 RESET_HOLD = 1 或 HQD ACTIVE = 0 不能证明队列资源已可释放。

11. 队列寄存器（HQD 与 Doorbell）

设备保存 4 组 HQD，每组占用 0x100 字节地址范围：槽 0 为 KIQ，槽 1 为 HIQ，槽 2、3 为用户 AQL 队列。全部寄存器为 32 位，小端且按 4 字节对齐；设备整体复位时清零，单独 CP 复位保留。

CP 记录首次非零错误后，后续非零错误不覆盖它。读取 HQD、确认中断或清除全局错误都不清除此值。CP 只能在 ACTIVE = 0 后清零，且必须先确认旧队列的相关访问结束；错误时清除 ACTIVE 不等于槽位或资源已经可复用。

11.5 BAR4 Doorbell

每条队列使用独立入口，由 CP_HQD_PQ_DOORBELL_CONTROL 指定 BAR4 内的字节偏移并使能。BAR4 大小为 64 KiB，合法入口偏移为 0x0000～0xfff8，必须按 8 字节对齐。

位域写入值（64 位，小端）
31:0已发布包的 32 位编号。
63:32必须为 0。

每次完整写入 8 字节；宽度、对齐或高 32 位非法时，拒绝通知并置位 ERROR_STATUS.INVALID_CMD。读取返回 0，不保存可供读回的通知值。只有激活且 Doorbell 已使能的匹配 HQD 才接收通知；没有匹配项时不改变队列状态。

Doorbell 只提示队列有工作，不更新生产或消费进度。重复、合并和乱序通知均允许；CP 仍根据共享生产进度及当前包的发布状态按序取包，不能把通知值当作消费进度。

12. Warp/Lane 只读启动 CSR

计算线程启动时已经取得代码入口和参数地址，接下来用 CSR 读取自己的坐标与工作规模。每次创建新 Warp 时，执行器保存共享启动状态，再填写各有效 Lane 的线程坐标、PC、mhartid 和 a0：

新 Warp → startup_sgpr[9]：blockIdx、blockDim、gridDim，各含 X/Y/Z
       └→ 每个有效 Lane 的 startup_vgpr[3]：threadIdx.x/y/z
                  └→ CSRRS 只读 → 写入目标通用寄存器

同一 Warp 分段续跑：保留启动状态
下一个 Warp 开始：重新填写启动状态

这些启动值与 Kernel 可覆盖的通用寄存器分开保存。目标通用寄存器被改写后，再次读取 CSR 仍得到原来的值。坐标按 X 维变化最快的顺序计算，gridDim 保存 Block 数量。例如 blockDim 为 (8, 4, 1) 时，组内线性线程 10 的 threadIdx 为 (2, 1, 0)。

12.1 CSR 编号与访问规则

CSR 编号名称读取内容
0xCC0～0xCC2THREAD_ID_X / Y / Z当前 Lane 的组内线程坐标。
0xCC3～0xCC5BLOCK_ID_X / Y / Z当前 Warp 所属 Block 的网格坐标。
0xCC6～0xCC8BLOCK_DIM_X / Y / Z每个 Block 的三维线程数。
0xCC9～0xCCBGRID_DIM_X / Y / Z网格的三维 Block 数量。

只接受 CSRRS 且 rs1 编码为 x0 的读取形式；rs1 指向其他寄存器时，即使该寄存器值为 0 也属于写请求。rd=x0 时仍检查 CSR 编号，再丢弃读取结果。未知 CSR、写请求和其他未支持形式报指令执行错误。mhartid 保留 0xF14 编号及第 14.3 节的编码。

汇编器接受 csrr rd, csr 与 csrrs rd, csr, rs1，CSR 操作数可以是 0～4095 的数字或 .equ 常量。csrr 编码为 CSRRS rs1=x0。该接口仅提供启动值，不实现可写 SGPR/VGPR 或完整标量、向量指令体系。

13. 完成顺序与同步边界

任务成功后，CP 先写 Signal，再写通知槽并提交 IH，之后将包 Header 置为 INVALID，最后更新消费进度。等待方读取 Signal 确认完成后再读取计算结果；队列和存储的回收还需要排空并确认队列卸载。

当前执行器不提供组间或跨 Warp 屏障。旧 BAR0 的 THREAD_MASK、BARRIER 和线程身份教学寄存器已移除，线程身份统一通过第 12 章的 CSR 获取。

14.4 Warp 执行规则¶

  • 每轮依次推进所有活跃 Lane 各一条指令；各 Lane 保存独立 PC。

  • 当 active_mask == 0 时 Warp 执行结束。
  • 每 Warp 最多执行 100,000 轮，各分段累计计数，超出后任务报 BUDGET 错误。

14.5 GPU 核心内存地址空间¶

计算线程的 a0 直接保存派发参数地址：GPUVM 开启时解释为 GPUVA，关闭时解释为 GPU 物理地址。参数读取、整数及浮点读写、取指均经过同一个用户访问入口；实际物理路由见4.5 节。

GPUVM 开启时，0x8000_0000 和 0x9000_0000 都是普通 GPUVA。关闭时，两者只按 VRAM／Outbound 布局解释。线程坐标从 CSR 读取，参数按普通内存处理，只有派发与取指保留声明范围检查。

RV32 计算线程的 GPU 地址空间与 RV64 CP 的本地地址空间分别解释。CP 本地 0x8000_0000 窗口仍然存在，不对应计算线程的特殊页面。

17. GPUVM 上下文与地址翻译

设备属性 gpuvm=on/off 在启动时固定，默认开启。两种状态都通过 AQL Queue、RV64 CP 与 Signal/IH 完成计算。GPUVM 开启时，用户访问沿下列路径翻译：

源 HQD / 任务快照 → VMID 1 或 2 → GPU 物理页表根
  → TLB 命中，或经公共物理入口读取三级页表 → 检查权限
  → GPU 物理地址 → 公共物理入口 → VRAM 或 Outbound
  → 返回数据，失败时保存源槽首次故障

关闭 GPUVM 时不创建页表，输入直接交给公共物理入口。队列仍保存 VMID 和源槽以便归属错误与管理资源，但用户共享物理地址空间，不提供页权限隔离。管理访问由显式访问域指定，与 VMID 是否为 0 无关。

下面寄存器均以对齐的 32 位小端值访问。未列出的读取返回 0；非法写入保留目标状态并设置全局 INVALID_CMD。GPUVM 关闭时保留版本、模式、固件握手和源槽故障记录，拒绝页表配置与失效请求。

17.1 模式与固件握手

BAR0 偏移寄存器访问复位值行为
0x0900VM_VERSIONHost / CP R3本版统一访存接口版本，固定为 3。
0x0904VM_MODEHost / CP R启动配置GPUVM 开启时为 1，关闭时为 0。
0x0908VM_FIRMWAREHost R / CP R/W0CP 在两种状态下均检查设备版本，再写 3。其他写值非法；CP 单独复位也清零。

CP 通过 0xfffd_0000 + BAR0 偏移 读取本组寄存器并发布握手。上下文和失效仅由 Host 配置，CP 不得通过该窗口修改。

17.2 页表根、使能与失效

上下文基址为 0x0940 + VMID × 0x20，用户 1、2 分别对应 0x0960、0x0980。每组只实现以下字段，复位均为 0：

组内偏移寄存器访问行为
0x00ROOT_LOHost R/W / CP R页表根的 GPU 物理地址低 32 位，按 4 KiB 对齐；仅禁用上下文时允许修改。

Host IOVA 0x4100_0000 → GPU 物理地址 0x4500_0000
设备访问 0x4500_0000 → 减去 GPU_BASE → IOVA 0x4100_0000 → PCIe DMA

IOVA 0 对应 GPU 物理地址 vram_size，位于 Outbound 起点。窗口覆盖只说明路由存在，Host 存储或 IOMMU 映射缺失时访问仍会失败。所有范围与末端计算使用 64 位数，完整地址空间末端为 0x1_0000_0000，不把这个值写入 RV32 地址字段。

18.1 寄存器映射（0x0b00）

各项通过 BAR0 以对齐的 32 位小端值访问。GPU_BASE 只有低 32 位，窗口长度及 Host IOVA 基址各用两项保存。布局只读，固定连续覆盖 VRAM 末端到 4 GiB，Host IOVA 基址为 0：

BAR0 偏移寄存器Host 访问复位值含义
0x0b00OUTBOUND_GPU_BASERvram_sizeGPU 物理窗口起点。
0x0b04OUTBOUND_SIZE_LOR窗口长度低 32 位长度为 0x1_0000_0000 − vram_size。
0x0b08OUTBOUND_SIZE_HIR窗口长度高 32 位与 SIZE_LO 组成完整 64 位长度。
0x0b0cOUTBOUND_HOST_LOR0Host IOVA 起点低 32 位，本版为 0。
0x0b10OUTBOUND_HOST_HIR0Host IOVA 起点高 32 位，本版为 0。
0x0b14OUTBOUND_CONTROLR/W0bit 0 为 ENABLE；其他位必须为 0。
0x0b18OUTBOUND_STATUSR0bit 0 ACK，bit 1 BUSY，bit 2 ERROR。

18.2 配置确认与停止条件

驱动在 CP 启动前读回核对基址和长度，再写 CONTROL 使能并读回 ACK。布局寄存器只读，写入置 OUTBOUND_STATUS.ERROR 并锁存 INVALID_CMD；合法 CONTROL 写入置 ACK。非法写入保留原配置，状态置 ERROR，并记录全局 INVALID_CMD。BUSY 反映物理在途访问。

窗口由全设备共用，创建 BO、Queue 或切换进程时均不修改。写 CONTROL 要求 CP 保持复位、所有 HQD 停用、执行器和 DMA、IH 不忙且物理在途计数为零；基址和长度始终只读。停止时先确认设备访问已经结束，才能关闭窗口或重新初始化。CP 单独复位保留窗口；设备整体复位恢复上述初值并停用。

# QEMU Camp Tutorial

QEMU Camp Tutorial 是 QEMU 训练营的在线技术文档，聚焦 C/Rust 语言与 QEMU 虚拟化/模拟器技术的深度结合，旨在通过系列技术博客、代码示例、原理解析，帮助开发者理解 QEMU 内部机制（如设备模拟、内存虚拟化、中断处理等），并掌握用 C/Rust 开发 QEMU 组件、优化 QEMU 模块的方法。​
