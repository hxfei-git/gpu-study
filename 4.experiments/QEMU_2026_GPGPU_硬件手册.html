本手册定义本仓库 GPGPU 虚拟加速器的地址空间、寄存器、访问规则和计算指令集。CP 为 RV64 控制核，应用 Kernel 由 RV32 计算执行器运行。寄存器偏移均为字节偏移；本设备的接口不代表 AMD 实体 GPU 的寄存器规格。

1. 概述¶

GPGPU 是为 QEMU 训练营定制的虚拟 PCIe 3D 加速器设备。其设计目标是提供一个覆盖 GPU 关键子系统的硬件抽象，用于：

  • PCIe 设备建模（BAR 映射、MSI-X 中断、配置空间）
  • DMA 引擎建模（Host↔VRAM 双向传输）
  • SIMT 执行模型（Warp 锁步、线程层次）
  • RISC-V 指令集解释器（RV32I + RV32F + 低精度浮点扩展）

2. 文档约定¶

2.1 数值与端序¶

  • 除非特别说明，所有数值均为十六进制，形如 0x1001_8000（下划线仅用于分组）。
  • 地址均为 字节地址（byte addressable）。
  • 所有多字节寄存器访问均按 小端序（little-endian） 解释。

2.2 术语¶

  • 未定义（undefined）：实现可以产生任意结果；软件不得依赖其行为。
  • 实现定义（implementation-defined）：实现必须在某处给出选择；若未给出，软件仍不得依赖。
  • R / W / R/W / W1C：分别表示只读、只写、可读写、写 1 清除；W1C 位写 0 不改变状态。表中复位值指设备冷复位或 GLOBAL_CTRL.RESET 后的值，单独 CP 复位的影响另行列出。

3.4 双进程的 BAR、DMA 与中断路径¶

[DESIGN] A57 Linux 运行在进程 A，通过 vfio-user-pci 访问进程 B 的 gpu0。进程 B 使用 gpgpu-cp machine，包含原有寄存器、VRAM、DMA、中断与计算解释器，以及由 TCG 执行的原生 RV64 CP。CP 默认保持复位；原同步计算和 DMA 可继续使用。

进程 A：A57 Linux
  └─ PCIe 设备代理
       ├─ 配置空间、BAR0/BAR2/BAR4 请求 ─→ 进程 B：GPGPU
       ├─ PCI DMA 接口 ←─ B 的读写请求       ├─ 原计算解释器
       │    └─ SMMUv3（启用时）→ Host RAM    └─ 原生 RV64 CP
       └─ Linux 驱动 ←─ 完成与错误中断            └─ 访问同一份 VRAM

none 与 smmuv3 都使用 x-dma-via-socket=on：B 把设备 DMA 地址、方向和数据请求发送给 A，A 调用该 PCI 设备的 DMA 接口，并返回数据或错误。SMMUv3 的翻译、权限检查和故障记录保留在 A。该启动选项只选择通信方式，不增加硬件寄存器。

BAR 访问通过消息转发，MSI-X 表和屏蔽状态在两端同步。计算完成、DMA 完成和错误事件沿原有向量传给 A 的 Linux 驱动。DMA 继续同步搬运数据，并通过原定时器报告完成。本版不支持断线重连和迁移。

4.3 MMIO 访问规则¶

  • BAR0 寄存器采用小端、4 字节对齐的 32 位访问。64 位地址由低、高两个寄存器保存，完整地址为 (HI << 32) | LO；不得用一次 64 位访问代替两次寄存器访问。
  • BAR2 VRAM 支持 1～8 字节访问。BAR4 Doorbell 的访问规则见 11.5 节。
  • 表中标记为保留的位必须写 0；读值及非法访问的处理以各寄存器组的规定为准。
  • BAR0 非法宽度或未对齐访问不更新目标寄存器，读返回 0，并置位 ERROR_STATUS.INVALID_CMD。IH 区域还记录 PROTOCOL 故障。HQD 和 CP 本地入口的权限见各节。
  • CP 控制窗口只开放分发、IH 和全局错误入口；访问其他寄存器组时读取返回 0，并置位 ERROR_STATUS.INVALID_CMD。组内保留位置按各组规则处理。未映射的 CP 地址产生访存异常，HQD 槽号不截断或折返。

6.5 软复位行为¶

写 GLOBAL_CTRL.RESET = 1 后，设备停止 CP 与计算任务，清零全局控制、错误、中断、分发配置、SIMT、DMA、HQD、Doorbell 提示和 IH 状态；GLOBAL_STATUS 恢复 READY，DISPATCH_STATUS 恢复 IDLE。已连接的 CP 保持复位，启动入口与 Host 窗口基址清零。VRAM 内容保留。单独 CP 复位的范围见 10.5 节。

7.3 IH 寄存器（0x0800）

IH 将 CP 提交的中断记录写入 Host RAM 中的环形缓冲区。以下寄存器均为 32 位；CP 地址为 0xfffd_0000 + BAR0 偏移。访问列按“Host / CP”列出权限。

BAR0 偏移寄存器Host / CP复位值定义
0x0800IH_BASE_LOR/W / R0Ring 完整物理字节地址的低 32 位。
0x0804IH_BASE_HIR/W / R0Ring 完整物理字节地址的高 32 位。
0x0808IH_SIZER/W / R0Ring 字节容量，至少 32 字节且为 2 的幂；0 表示尚未配置。
0x080cIH_WPTRR / R0下一条待写记录的 32 位编号，由 IH 推进。
0x0810IH_RPTRR/W / R0下一条待读记录的 32 位编号，由 Host 回报。
0x0814IH_STATUSR / R0忙状态、首次故障及最近一次提交结果。
0x0818IH_CTRLR/W / R0使能与通道复位。
0x081cIH_SUBMIT禁止写 / W—写入临时记录的 32 位 VRAM 偏移；读取返回 0。

IH_BASE 按 4 KiB 对齐，基址加容量的完整范围不得溢出。只有 ENABLE = 0 且 BUSY = 0 时，Host 才能改写基址和容量；使能时检查配置。向只读项、未定义位置或以错误权限写入，记录 PROTOCOL 故障，不改变目标配置。

ERROR_CODE 和 LAST_SUBMIT_RESULT 使用以下独立编号，分别保存；它们不是位掩码。

值名称含义

1DISABLED通道未使能时提交。
2CONFIGRing 基址、容量或范围非法。
3FULLRing 已满，没有可写槽位。

故障置位 IH_STATUS.FAULT 和全局 ERROR_STATUS.IH_FAULT，经 IRQ_STATUS.ERROR 通知。已有故障时拒绝新记录；首次满环提交可得到 ERROR_CODE = 3，再次提交时前者保持 3，而 LAST_SUBMIT_RESULT = 7。

7.5 IH_SUBMIT 与记录发布

CP 在固件私有 VRAM 的 0x03c0_0000～0x03ff_ffff 内准备一条 32 字节、小端记录，起始偏移至少按 8 字节对齐，整条记录必须位于该范围内。先保证记录内容可见，再将起始偏移写入 IH_SUBMIT。写操作同步返回；CP 随后读取 LAST_SUBMIT_RESULT，此时可复用临时缓冲区。

记录内偏移位宽含义
0x0032类型：1 = SIGNAL_NOTIFY，2 = QUEUE_ERROR，3 = DEVICE_ERROR。
0x0432HQD 槽号：SIGNAL_NOTIFY 为 2～3；QUEUE_ERROR 为 0～3；DEVICE_ERROR 为 0xffff_ffff。
0x0864完整 MQD 物理字节地址，至少按 8 字节对齐；DEVICE_ERROR 填 0。
0x1032类型 1：非零事件编号；类型 2：CP_HQD_ERROR 编号 1～10；类型 3：非零全局错误位掩码。
0x14～0x1f96保留，填 0。

令 N = IH_SIZE / 32，记录地址为 IH_BASE + (IH_WPTR mod N) × 32。WPTR、RPTR 均按模 2^32 推进，不是字节偏移。(WPTR − RPTR) mod 2^32 = N 时 Ring 满，设备拒绝新记录，不覆盖未消费记录；写入失败不推进 WPTR。

设备先完整写入记录，再发布 WPTR，最后置位 IH 中断。Host 读取发布进度并同步后消费记录，再写回 RPTR；新 RPTR 的前进量不能超过尚未消费的记录数。更新 RPTR 后，向 IRQ_ACK 的 bit 3 写 1；若 Ring 仍非空，IH 位立即重新置位并再次通知。ACK 不推进 RPTR，也不清除 IH 故障；重新使能 IH 中断时，非空 Ring 同样产生通知。

8.2 编程模型¶

Host 同步提交和 CP 队列提交互斥；激活 HQD 或由 CP 接受任务后进入队列模式，Host 对分发区的写入被拒绝，直到设备整体复位。

Host 同步提交：装载 VRAM 代码及参数，配置代码与参数偏移、非零 Grid/Block 尺寸，保证配置写入完成后写 DISPATCH。设备完成计算后清除 GLOBAL_STATUS.BUSY，置位 IRQ_STATUS.KERNEL_DONE；失败通过全局错误报告。长度与 DISPATCH_STATUS 结果握手用于 CP 提交，同步路径仍使用原有完成中断。

CP 提交：在 IDLE 时写入代码入口、代码长度、完整 Host 参数地址、参数长度和 Grid/Block 尺寸，最后向 DISPATCH 写 1。设备锁存配置，校验通过进入 BUSY；校验失败直接进入 FAILED。计算和相关访问结束后发布 DONE 或 FAILED，CP 读取结果并写 ACK，执行器才能接受下一任务。队列完成通知通过 IH，不直接产生同步路径的 KERNEL_DONE 中断。

CP 提交时，Host 参数基址至少按 8 字节对齐，基址加长度不得溢出；无参数任务也提供 4 字节占位参数。各轴 Grid/Block 尺寸必须非零，每组最多 1024 个线程，最多 4096 个工作组，实际线程总数最多 65536；未使用轴填 1，SHARED_MEM_SIZE 填 0。

10. CP 控制寄存器¶

CP 的低地址映射到相同偏移的 VRAM。默认 64 MiB 配置中，0x03c0_0000～0x03ff_ffff 保留给 CP 固件，入口为 0x03c0_0000，最后 64 KiB 为栈。Host 经 BAR2 装载固件，写入入口并确认存储可见后解除复位。

CP 通过 0x8000_0000～0x8000_ffff 的 64 KiB 窗口访问 Host RAM，支持按访问宽度对齐的 1/2/4/8 字节读写。下列 32 位小端寄存器保存目标基址和访问上下文，仅 CP 可访问，Host 无 BAR0 对应项。GPUVM 用户域也通过此窗口访问 VRAM 后备对象。

10.5 复位范围与固件替换

CP 单独复位保留 VRAM、启动入口、HQD、IH、DMA、分发和中断状态，清零 CP 访存窗口配置及 GPUVM 固件握手，保留 GPUVM 上下文与 TLB；它不停止已有计算任务或清理队列。GLOBAL_CTRL.RESET 停止计算并复位设备寄存器，保留 VRAM；设备冷复位还清零 VRAM。

替换固件前须确认相关计算和访存已结束，再保持 CP 复位并读回确认、装载固件、设置入口、保证写入可见，最后解除复位。仅观察到 RESET_HOLD = 1 或 HQD ACTIVE = 0 不能证明队列资源已可释放。

11. 队列寄存器（HQD 与 Doorbell）

设备保存 4 组 HQD，每组占用 0x100 字节地址范围：槽 0 为 KIQ，槽 1 为 HIQ，槽 2、3 为用户 AQL 队列。全部寄存器为 32 位，小端且按 4 字节对齐；设备整体复位时清零，单独 CP 复位保留。

11.5 BAR4 Doorbell

每条队列使用独立入口，由 CP_HQD_PQ_DOORBELL_CONTROL 指定 BAR4 内的字节偏移并使能。BAR4 大小为 64 KiB，合法入口偏移为 0x0000～0xfff8，必须按 8 字节对齐。

位域写入值（64 位，小端）
31:0已发布包的 32 位编号。
63:32必须为 0。

每次完整写入 8 字节；宽度、对齐或高 32 位非法时，拒绝通知并置位 ERROR_STATUS.INVALID_CMD。读取返回 0，不保存可供读回的通知值。只有激活且 Doorbell 已使能的匹配 HQD 才接收通知；没有匹配项时不改变队列状态。

Doorbell 只提示队列有工作，不更新生产或消费进度。重复、合并和乱序通知均允许；CP 仍根据共享生产进度及当前包的发布状态按序取包，不能把通知值当作消费进度。

14. 执行模型¶

14.1 线程层次¶

Grid (grid_x × grid_y × grid_z 个 Block)
 └─ Block (block_x × block_y × block_z 个线程)
     └─ Warp (最多 32 个 Lane, 锁步执行)

14.2 每 Lane 寄存器¶

寄存器 数量 宽度 描述
x0–x31 32 32-bit 通用寄存器（x0 恒为 0）
f0–f31 32 32-bit 浮点寄存器（IEEE 754 单精度）

fcsr 1 8-bit 浮点控制状态

14.3 mhartid 编码¶

Bit [31:13]  block_id_linear   (19 位，最多 524,287 个 Block)
Bit [12:5]   warp_id           (8 位，最多 256 个 Warp)
Bit [4:0]    thread_id (lane)  (5 位，0–31)

GPU 核心通过 csrrs x6, mhartid, x0 读取，用 andi x6, x6, 0x1F 提取 lane ID。

14.4 Warp 执行规则¶

  • 所有活跃 Lane 执行同一条指令（SIMT 锁步）。
  • Lane 遇到 ebreak 或 ret（ra=0）时退出，对应 active_mask 位清零。
  • 当 active_mask == 0 时 Warp 执行结束。
  • 每 Warp 最大 100,000 周期，超出则报 KERNEL_FAULT。

17. GPUVM 上下文与地址翻译

设备启动时用 gpgpu.gpuvm=on 固定开启用户地址翻译。用户 Queue 已有 VMID，CP 或执行器给出用户地址及访问类型，设备按以下路径取得实际存储：

源 HQD / 任务快照 → VMID 1 或 2 → 上下文的 VRAM 页表根
  → TLB 命中，或遍历三级页表 → 检查读、写、取指权限
  → VRAM 页偏移，或 Host DMA 地址 → 返回数据 / 保存源槽首次故障

VMID 0 表示受信任的管理 DMA 直通，不占用用户页表窗口。下面寄存器均以对齐的 32 位小端值访问。未列出的读取返回 0；非法写入保留目标状态并设置全局 INVALID_CMD。GPUVM 关闭时仍可读取版本和模式，拒绝 GPUVM 配置写入。

17.1 模式与固件握手

BAR0 偏移寄存器访问复位值行为
0x0900VM_VERSIONHost / CP R1本版设备接口版本，固定为 1。
0x0904VM_MODEHost / CP R启动配置GPUVM 开启时为 2；关闭时为 0，不区分旧同步与旧物理队列模式。
0x0908VM_FIRMWAREHost R / CP R/W0CP 检查模式和版本后写 1。其他写值非法；CP 单独复位也清零。

CP 通过 0xfffd_0000 + BAR0 偏移 读取本组寄存器并发布握手。上下文和失效仅由 Host 配置，CP 不得通过该窗口修改。

17.2 页表根、使能与失效

上下文基址为 0x0940 + VMID × 0x20，用户 1、2 分别对应 0x0960、0x0980。每组只实现以下字段，复位均为 0：

组内偏移寄存器访问行为
0x00ROOT_LOHost R/W / CP R页表根的 VRAM 字节偏移低 32 位，按 4 KiB 对齐；仅禁用上下文时允许修改。
0x04ROOT_HIHost R/W / CP R本版 VRAM 表地址高 32 位必须为 0；仅禁用上下文时允许修改。
0x08ENABLEHost R/W / CP R完整值 0 或 1；启用前检查根页完整落在普通 VRAM 区间。

有激活的所属用户 HQD 或该 VM 在途访存时，拒绝修改根和使能。启用本身不失效 TLB；配置顺序为禁用、写根和页表、保证可见、完成失效、启用。仅看到 ACTIVE=0 不能替代软件的卸载完成检查。

BAR0 偏移寄存器访问复位值行为
0x0910VM_INVALIDATEHost W—完整写入 VMID 1 或 2，按该编号全量失效；读取为 0。
0x0914VM_STATUSHost / CP R0bit 0 BUSY，bit 1 ACK，bit 2 ERROR；其余位为 0。

接受请求时先清旧 ACK，置 BUSY。编号非法、所属 HQD 激活或有在途访问时，返回 ERROR。合法请求清除该 VMID 的全部缓存项，再以 ACK 结束；仿真中同步完成，因此 Host 通常直接读到终态。失效在设备锁内串行执行，在途访问计数阻止旧遍历重新填充。ACK 表示本次翻译失效，不代替先结束数据访问的卸载协议。

17.3 页表格式与访问检查

32 位 GPUVA 分为根索引 [31:30]、下级目录索引 [29:21]、叶表索引 [20:12] 和页内偏移 [11:0]。每张表占 4 KiB，64 位小端表项共 512 个，根只使用前 4 个。页表遍历直接读取 VRAM，不递归经过用户页表。

位名称PDEPTE
0VALID下级目录有效目标页有效
1SYSTEM必须为 01 为 Host DMA；0 为 VRAM
4 / 5 / 6EXEC / READ / WRITE必须为 0分别允许取指、读取、写入
47:12ADDRESS下一级 VRAM 表页地址目标页地址
其余位保留有效项中必须为 0；非法编码报页表错误。

地址掩码为 0x0000_ffff_ffff_f000。表页和 VRAM 目标页必须完整落在 0x1000～0x03bf_ffff，不能触及首个保留页或末尾固件区。软件负责保证表页不作为用户 BO 映射。SYSTEM 目标保存 DMA 地址；SMMUv3 开启时该地址还需经过系统 IOMMU。

TLB 使用 64 项小型直接映射缓存，以 VMID 和 GPU 页号区分，并保存权限。访问先检查已启用的上下文、完整 32 位地址范围和自然对齐，再逐页检查目标与权限。翻译失败不尝试物理地址；跨页传输在后页失败时保留前面已经完成的写入，不自动重试或回滚。

17.4 首次故障与复位

故障组基址为 0x0a00 + HQD 槽号 × 0x40，四组独立。访问入口携带源槽；每槽只保存首次错误，后续错误不覆盖。下面字段复位均为 0：

组内偏移字段Host 访问含义
0x00REASONR0 无故障；1 上下文；2 地址范围或对齐；3 未映射；4 非法页表；5 权限；6 后备存储访问失败。
0x04VMIDR出错访问携带的 VMID。
0x08 / 0x0cADDR_LO / ADDR_HIR原始访问地址低、高 32 位；正常用户 GPUVA 的高位为 0。
0x10ACCESSR取指 0x10、读 0x20、写 0x40。
0x14PHASERCP 沿用 HQD 错误阶段；执行器取指为 0x100，参数读取为 0x101，数据访问为 0x102。
0x18CLEARW源 HQD 未激活时完整写 1，清除此组；读取为 0。软件须先确认旧访问和通知结束。

故障记录不自行发送额外中断。CP 窗口返回访存异常，计算执行器返回失败，固件沿已有源队列错误和 IH 路径通知 Host；另一 VM 可以继续运行。整体复位清除上下文、TLB、故障、失效状态和固件握手；CP 单独复位仅清窗口与握手，保留 GPUVM 状态和已有执行任务。
